Lindy gives your coding agent an app map: the data an application holds, the actions that change it and the views that show it. The agent can inspect that map, propose a scoped change for your review and deterministically compile the approved source.

Work from meaning

In the reading-list sample, the editor shows Save changes but not Remove item. The graph already describes how to remove an item. Your agent can follow the editor’s connections to that operation and propose exposing it, without changing the backend or rebuilding the list.

Keep review in the loop

Ask for the visible outcome: add a confirmed Remove item action while preserving the list and edit flow. The agent inspects those declarations and proposes an edit. You review what changes and what stays intact before approving. Lindy rejects a patch if its expected graph revision no longer matches the project.

Compile the approved source

Compilation turns supported graph declarations into application files, called artifacts. Given the same declared inputs, it produces the same bytes. A runtime binding supplies the actual data functions—for example, reading the sample’s saved items. Make the next change in semantic source, not in generated JavaScript.

Start locally

Try the portable, editable reading-list sample with the supplied preview archive and Node/npm. Reading List Walkthrough shows the app before connecting an agent and then one reviewed semantic change. Source setup remains for contributors; it is not required by the portable runtime.

This documentation website is itself built with Lindy. Its application graph and typed content show how semantic behavior, application data and reusable presentation fit together.

Where to go next

Read Semantic Graph to understand the application model, Review a Change for the authoring loop, and Compile & Run for the boundary between compilation and a running application.
