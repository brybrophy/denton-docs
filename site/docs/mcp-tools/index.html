CLI & MCP

On this page

The local CLI and MCP server expose the same project operations. Your coding agent uses MCP to inspect and edit the selected application; integrations can call the CLI directly with typed JSON requests.

Select a project

The CLI uses --project to select a graph file. Init writes local client templates that pin the installed Node/CLI and reading-list graph. Attach them manually; the MCP connection selects one project at server startup. Keep the installed tools/project paths stable.

Eight tools

  • lindy.search finds declarations by semantic query.
  • lindy.inspect returns a declaration and its relationships.
  • lindy.propose validates a candidate edit without applying it.
  • lindy.patch applies a patch to its expected revision.
  • lindy.validate checks application structure and architecture.
  • lindy.affected identifies impacted declarations.
  • lindy.compile compiles a revision and selects its generated artifacts.
  • lindy.artifact reads a bounded artifact chunk.

Search, inspection, proposals, validation, affected analysis and artifact reads are read-only. Patch changes the graph. Compile writes compiler-owned output and selects the build; it does not deploy it.

Requests and results

Requests use strict schemas for the selected operation and application profile. Patch and compile carry expectedRevision; artifact reads also carry the current manifest hash. Unknown fields and incompatible profile selections are rejected. Use the current application configuration instead of copying a request from another example.

MCP results are in structuredContent. Generated bodies are read through lindy.artifact rather than duplicated into text messages. CLI requests can use a JSON file or standard input through --request; state-changing CLI invocations require --approve as an invocation acknowledgement, in addition to reviewing the semantic proposal.

Keep client review prompts

Init supplies project-local configuration templates; it does not register or start an agent and does not select a model. Retain manual per-call permissions. Codex uses:

toml
default_tools_approval_mode = "prompt"

Claude Code uses:

json
{"permissions":{"ask":["mcp__lindy__*"]}}

The server name and permission pattern must agree. Open /mcp after starting your client and confirm the eight raw tool names listed above. A tool permission prompt is separate from human approval of the proposed application behavior.

Content maintenance

The eight tools edit the application definition, not arbitrary data records. This site's typed documentation records use the application-specific docs:author API described in One Reviewed Change. Data Bindings explains that separation.
