One Reviewed Change

On this page

On this page

  • Inspect the source
  • Review one proposal
  • Apply the exact approved edit
  • Rebuild and observe

Follow a real editorial task: change one paragraph on Overview, review the proposed wording, then rebuild the site and find it in search. To run the commands yourself, you need a contributor checkout with Node.js 24.19.0, pnpm 11.21.0 and its frozen dependencies installed. Start in the repository root.

Inspect the source

The example changes one plain paragraph in the Overview page record. The graph still owns application routes and behavior.

text
Update the Overview introduction to explain our application more clearly.
Inspect its typed content first and propose one scoped edit.
Preserve the page ID, URL, navigation and existing links.
Show me the semantic diff and wait for approval before applying it.

Illustrative agent reply: “I found one plain paragraph in Overview at block 0. I’ll propose a clearer semantic blueprint introduction. I’ll preserve the page ID, URL, navigation and every existing link elsewhere on the page. I haven’t applied anything; I’m waiting for your review.”

The reply is illustrative, not a recorded model conversation. Tool excerpts below show the deterministic results for this example; omitted fields are noted. An agent may suggest different wording.

sh
node scripts/docs-author.mjs inspect --page overview > overview-inspect.json
node -e 'console.log(JSON.parse(require("node:fs").readFileSync("overview-inspect.json","utf8")).revision)'

The first command saves the actual inspect response; the second prints its full revision for the request template below. These selected raw inspect fields omit the document and that revision:

json
{
  "model": "docs.ContentPage",
  "pages": [
    {
      "id": "overview",
      "slug": "overview",
      "title": "Overview",
      "section": "Start Here"
    }
  ]
}

Review one proposal

Before — Denton gives your coding agent an app map: the data an application holds, the actions that change it and the views that show it. The agent can inspect that map, propose a scoped change for your review and deterministically compile the approved source.

After — Denton gives your coding agent a semantic blueprint of an application: its data, actions and views. The agent can inspect that model, propose one scoped change for your review, then deterministically compile the approved source into application artifacts.

Create overview-change.json using the template below. Replace <full revision from inspect> with the complete revision just printed; the placeholder is not a valid revision to submit. The operations contain the exact After paragraph above. This is a request template, not a tool response.

json
{
  "expectedRevision": "<full revision from inspect>",
  "operations": [
    {
      "kind": "set-block-text",
      "pageId": "overview",
      "blockIndex": 0,
      "text": "Denton gives your coding agent a semantic blueprint of an application: its data, actions and views. The agent can inspect that model, propose one scoped change for your review, then deterministically compile the approved source into application artifacts."
    }
  ]
}

set-block-text fits this plain paragraph. For a block containing links or marks, use replace-block and preserve its inline structure. This request changes only docs.ContentPage/overview, block 0, retaining page identity, URL, order, links and every other block.

sh
node scripts/docs-author.mjs propose \
  --request overview-change.json > overview-proposal.json
cat overview-proposal.json

Review the saved proposal before taking the next step. These are selected raw fields; the full response also contains revision hashes and before/after records:

json
{
  "valid": true,
  "changes": [
    {
      "semanticId": "docs.ContentPage/overview",
      "beforeOrder": 0,
      "afterOrder": 0
    }
  ]
}

A valid proposal is still read-only: the source has not changed. Review its exact Before/After and unchanged relationships. The response’s candidateRevision identifies the proposed new state; proposalHash binds the complete proposal. Keep both full values. Do not replace the source revision or edit overview-change.json after review.

Apply the exact approved edit

Example human approval: “Approve exactly this Overview paragraph change. Apply the reviewed request with its full proposal hash.” This message is human approval, not a tool result or automatic permission.

After that human approval, read proposalHash from the same overview-proposal.json and pass it through --approve while reusing the unchanged overview-change.json. The CLI adapter sends this value internally as approvalHash. Neither proposalHash nor approvalHash is a field to add to the request file; expectedRevision is its separate source-state check.

sh
proposalHash=$(node -e 'const p=JSON.parse(require("node:fs").readFileSync("overview-proposal.json","utf8")); if(!p.valid) process.exit(1); console.log(p.proposalHash)')
node scripts/docs-author.mjs apply \
  --request overview-change.json \
  --approve "$proposalHash"

Selected raw apply field:

json
{
  "applied": true
}

On success, revision equals the proposal’s candidateRevision and previousRevision equals the inspected revision. If the source changed, the old request fails with Documentation authoring: stale-revision. Inspect and propose again rather than substituting a new revision into an approved request. If the apply response is uncertain, inspect current state before retrying.

sh
node scripts/docs-author.mjs validate

Selected raw validation fields (the new revision is omitted):

json
{
  "valid": true,
  "pages": 18
}

Rebuild and observe

After apply and validate succeed, run the next command from the repository root. It builds a fresh local preview of the edited source; it does not update the hosted website.

sh
pnpm docs:preview

Open the preview’s loopback URL at /docs/overview. Its first paragraph should now read:

Denton gives your coding agent a semantic blueprint of an application: its data, actions and views. The agent can inspect that model, propose one scoped change for your review, then deterministically compile the approved source into application artifacts.

Search blueprint in that rebuilt local site. Overview now matches because the approved After paragraph contains that word. This walkthrough may also match because it quotes the example. This observation concerns your local release, not a change to the hosted public website.

The tutorial does not apply its After paragraph to the real Overview. Source changes require your reviewed request and approval; a local preview does not publish the result. Generated HTML, projected Markdown and runtime files are outputs, not maintenance inputs.

The same API can add a page with its title, slug, section and position in one reviewed candidate. Include inbound link changes in that request when needed. Changes to graph behavior use the separate Review a Change workflow; Artifacts explains build identity.
